CRITICAL DCSync Rights: CONTOSO\svc-azuread-sync T1003.006

The identity CONTOSO\svc-azuread-sync has DS-Replication-Get-Changes-All rights on the domain object. An attacker who compromises this account can replicate ALL credential hashes from the domain including the KRBTGT hash, enabling Golden Ticket attacks.

▶ Show exploit details & remediation
HOW AN ATTACKER ABUSES THIS
mimikatz # lsadump::dcsync /user:krbtgt
impacket-secretsdump CONTOSO/svc-azuread-sync@DC01.contoso.local
SAFE REMEDIATION (Risk: LOW)
1) Verify if this account is Azure AD Connect. If yes, check if DS-Replication-Get-Changes-All is actually needed (it is NOT required for Password Hash Sync). Run Azure AD Connect wizard in Express mode to reset permissions.
2) If not Azure AD Connect: remove the right immediately via ADSI Edit > domain root > Properties > Security.
3) Monitor Event ID 4662 for unauthorized replication requests.

CRITICAL Unconstrained Delegation: WEB-SRV-01 (Windows Server 2019) T1558.001 NEW

Computer account WEB-SRV-01$ has TrustedForDelegation=True. Any authenticated user whose TGT lands on this server (e.g., via the Printer Bug or coerced auth) can be captured and reused. This was added this week — likely a misconfigured IIS deployment.

▶ Show exploit details & remediation
ATTACK CHAIN
1. Compromise WEB-SRV-01 (web vuln, local priv-esc)
2. Run: Rubeus.exe monitor /interval:5 /nowrap
3. Coerce DC auth: SpoolSample.exe DC01 WEB-SRV-01
4. Capture DC01$ TGT → Pass-The-Ticket → DCSync
SAFE REMEDIATION (Risk: LOW)
1) Remove unconstrained delegation:
Set-ADComputer WEB-SRV-01 -TrustedForDelegation $false
2) If IIS needs impersonation, configure Constrained Delegation to specific SPNs only.
3) Reboot is NOT required. Change is immediate in AD.

DCSync: svc-azuread-sync has DS-Replication-Get-Changes-All
CRITICAL | Score 95
WHAT IS THE RISK?
Full credential replication capability. Can dump all hashes including KRBTGT.
WHY IS IT THERE?
Azure AD Connect misconfiguration — express setup grants DS-Replication-Get-Changes-All unnecessarily. Only DS-Replication-Get-Changes is required for Password Hash Sync.
MITRE: T1003.006 — DCSync
mimikatz # lsadump::dcsync /user:krbtgt /domain:contoso.local
Remediation Steps — Risk: LOW
Option A (Preferred): Re-run Azure AD Connect Express Setup wizard — it will reset permissions to minimum required.

Option B (Manual):
$acl = Get-Acl "AD:\DC=contoso,DC=local"
$ace = $acl.Access | Where-Object {
$_.IdentityReference -match "svc-azuread-sync" -and
$_.ObjectType -eq [Guid]"1131f6ab-..."
}
$acl.RemoveAccessRule($ace)
Set-Acl -Path "AD:\DC=contoso,DC=local" -AclObject $acl
Unconstrained Delegation: WEB-SRV-01 (New This Week)
CRITICAL | Score 92
ROOT CAUSE
Likely set during IIS Application Pool deployment. The installer may have automatically set TrustedForDelegation without administrator review.
IMPACT
Any user who authenticates to WEB-SRV-01 (including a Domain Admin browsing a web app) has their TGT exposed. Combined with the Printer Bug, this is a one-step path to DCSync.
Remediation — Risk: LOW (no reboot required)
Set-ADComputer -Identity "WEB-SRV-01" -TrustedForDelegation $false

Then configure Constrained Delegation if IIS truly needs impersonation:
Set-ADComputer "WEB-SRV-01" -Add @{"msDS-AllowedToDelegateTo"="HTTP/WEB-SRV-01"}
Kerberoastable Privileged: svc-sqlcluster (password 1,184 days old)
HIGH | Score 90
ROOT CAUSE
Service account with SPN and a 3+ year old password. Member of Domain Admins — this is the highest-priority Kerberoastable target in the domain.
EXPLOIT
Rubeus.exe kerberoast /user:svc-sqlcluster /nowrap
hashcat -m 13100 hash.txt rockyou.txt
Remediation — Risk: MEDIUM (service restart required)
Step 1: Migrate to Group Managed Service Account (gMSA) — eliminates Kerberoastability permanently.
New-ADServiceAccount -Name "gMSA-sql" -DNSHostName "SQL01.contoso.local"
Install-ADServiceAccount "gMSA-sql"

If gMSA not possible: Reset to 25+ char random password immediately. Set AES256 encryption to increase cracking difficulty:
Set-ADUser svc-sqlcluster -KerberosEncryptionType AES256
Attack Path — j.morrison → Domain Admins (2 hops)
👤 User: j.morrison ─── GenericAll ACE ───▶ 👥 Group: IT-Helpdesk ─── MemberOf (Nested) ───▶ 👑 Group: Domain Admins
Exploit Steps
  1. Compromise j.morrison — phishing, credential stuffing, or AS-REP roast if pre-auth disabled. Account is a shadow admin (AdminCount=1) making it a high-value target.
  2. Abuse GenericAll on IT-Helpdesk — Add any account to IT-Helpdesk:
    Add-ADGroupMember -Identity "IT-Helpdesk" -Members "attacker-account"
  3. Inherit Domain Admin via Nested Group — IT-Helpdesk is nested in Domain Admins (verified via recursive membership). Attacker now has full DA rights.
MITRE: T1098 Account Manipulation → Privilege Escalation
Root Cause
GenericAll ACE on IT-Helpdesk group was likely granted to j.morrison for "helpdesk management" but the group is nested in Domain Admins — a misconfiguration that creates a 2-hop DA path.
Remediation — Risk: LOW
Priority 1: Remove j.morrison's GenericAll ACE on IT-Helpdesk:
$acl = Get-Acl "AD:\CN=IT-Helpdesk,OU=Groups,DC=contoso,DC=local"
$ace = $acl.Access | Where IdentityReference -match "j.morrison"
$acl.RemoveAccessRule($ace); Set-Acl ...

Priority 2: Remove IT-Helpdesk nesting from Domain Admins — standard helpdesk should not be in DA.
Remove-ADGroupMember -Identity "Domain Admins" -Members "IT-Helpdesk"
